## Directory Purposes

**src/:**
- Purpose: All application source code
- Contains: React components, styles, API client, assets
- Key files: `App.jsx` (entire app), `main.jsx` (entry), `lib/supabase.js` (API)

**src/lib/:**
- Purpose: Reusable library code and external service abstractions
- Contains: Supabase client initialization and database functions
- Key files: `supabase.js` (only file here, 69 lines)

**src/assets/:**
- Purpose: Images, SVGs, and static assets
- Contains: React and Vite logos
- Key files: `react.svg`

**public/:**
- Purpose: Static assets copied directly to build output
- Contains: Main HTML document, brand assets
- Key files: `index.html` (meta tags, Google Fonts link)

**dist/:**
- Purpose: Production-ready bundled output
- Generated: Automatically by `npm run build`
- Committed: No (in .gitignore)

**android/:**
- Purpose: Native Android app wrapper via Capacitor
- Contains: Android-specific configuration, gradle files
- Deployed: Via Android Studio or `npx cap build android`

**supabase/:**
- Purpose: Backend infrastructure configuration
- Contains: Postgres migration files, Edge Functions (serverless endpoints)
- Notable: Edge Function `claude-proxy` handles Claude API calls server-side

**.planning/codebase/:**
- Purpose: GSD (Get Shit Done) analysis documents
- Contains: ARCHITECTURE.md, STRUCTURE.md, CONVENTIONS.md, TESTING.md, CONCERNS.md
- Generated: By CI/CD or manual GSD commands

## Key File Locations

**Entry Points:**
- `public/index.html`: HTML document root with viewport meta, font links
- `src/main.jsx`: React root initialization, DOM mount point
- `src/App.jsx`: Main React component, screen routing

**Configuration:**
- `package.json`: NPM dependencies, build scripts (dev, build, lint, preview)
- `vite.config.js`: Vite build tool configuration with React plugin
- `capacitor.config.json`: Capacitor mobile app config (appId, webDir)
- `eslint.config.js`: Code linting rules

**Core Logic:**
- `src/App.jsx`: 1565-line monolithic file containing:
  - Component definitions (AuthScreen, WorldMap, LocView, ToolsView, etc.)
  - State constants (THEMES, LANGS, LESSONS, TOOLS, ACHIEVEMENTS, etc.)
  - Custom hooks and managers (Streak system, TCache)
  - Styling (inline CSS-in-JS)
  - Main app orchestration and routing

**API Layer:**
- `src/lib/supabase.js`: Supabase client instantiation and CRUD operations
  - Auth: signUp, signIn, signOut, getSession, onAuth
  - Data: getProfile, updateProfile, getProgress, completeLesson
  - Integration: callClaude (calls Supabase Edge Function)

**Styling:**
- `src/index.css`: Global CSS variables, resets, animations (lumiFloat, fadeUp, pulse, celebrate, etc.)
- `src/App.css`: App-level CSS (if additional styles beyond inline)
- Inline styles: Every component uses `style={{}}` props in JSX

**Assets:**
- `src/assets/react.svg`: React logo (unused in current app)
- `public/vite.svg`: Vite logo (referenced in HTML)
- Font links in `public/index.html`: Nunito and Quicksand from Google Fonts

**Backend Integration:**
- `supabase/functions/claude-proxy/`: Edge Function that proxies Claude API calls
- Called via: `db.callClaude()` in `src/lib/supabase.js`
- Purpose: Securely call Anthropic Claude API from backend (hides API key)

## Naming Conventions

**Files:**
- Components: PascalCase, one component per logical feature (e.g., `AuthScreen`, `WorldMap`, `LocView`)
- Utilities: camelCase, descriptive names (e.g., `supabase.js`, `index.css`)
- HTML entry: `index.html` (standard convention)
- Build output: `dist/` (standard Vite convention)

**Components:**
- Main screens: PascalCase suffix "Screen" or "View" (AuthScreen, WorldMap, LocView, ProfileView)
- Sub-components: PascalCase descriptive (Lumi, Icon, Btn, ErrorMsg, Skeleton, ShareCard, etc.)
- Helpers: camelCase functions (locName, toolDesc, getLang, setTheme, etc.)

**Variables & Constants:**
- Themes: THEMES object with dark/light variants
- Language packs: LANGS, UI, LOC_NAMES, LOC_SUBS, LOC_DESCS, TOOL_NAMES, TOOL_DESCS, LESSON_TITLES
- Data structures: LOCS, LESSONS, TOOLS, ACHIEVEMENTS, DAILY_CHALLENGES
- State managers: Streak (custom manager with internal _ prefix for private methods)
- Internal globals: _theme, _lang, _isNative (module-level, not const to allow mutation)
- Configuration: C (current theme object), T (current language object)

**Styling:**
- Color variables: gold, green, teal, blue, purple, red, coral (semantic names)
- Component classes: Minimal CSS classes, mostly `className="fu"` (mysterious abbreviation)
- Inline styles: Use theme colors from C object (C.gold, C.text, C.bgCard, etc.)

## Where to Add New Code

**New Feature:**
- Primary code: Add component in `src/App.jsx`, new state management as needed
- Tests: Not currently used (see TESTING.md for concerns)
- Consider breaking out large components into separate files in future refactor

**New Lesson Content:**
- Add to `LESSONS` constant in `src/App.jsx`
- Structure: `{title, sections: [{h, body}], questions: [], practice: []}`
- Location learning path: Link in LOCATIONS entry

**New Learning Path/Location:**
- Add to `LOCS` array in `src/App.jsx`
- Add translations to `LOC_NAMES`, `LOC_SUBS`, `LOC_DESCS`
- Create matching `LESSONS[pathId]` array

**New Tool/Workflow:**
- Add to `TOOLS` array in `src/App.jsx`
- Structure: `{id, name, desc, steps: [{q, opts?, free}], sys: systemPrompt}`
- Update `ToolsView` component if special UI needed
- Claude system prompt in `sys` field guides API response

**New Achievement:**
- Add to `ACHIEVEMENTS` array with condition function
- Condition evaluates (progress, profile) → boolean
- `MilestoneCheck` and `AchievementsView` read from this array

**Utility Functions:**
- Language helpers: `locName()`, `locSub()`, `locDesc()`, `toolName()`, `toolDesc()`, `lessonTitle()`
- Theme helpers: `setTheme()`, `getTheme()`
- Language helpers: `setLang()`, `getLang()`, `isRTL()`
- Streak helpers: `Streak.check()`, `Streak.recordActivity()`, `Streak.getCalendar()`

## Special Directories

**dist/:**
- Purpose: Build artifact directory
- Generated: `npm run build` creates optimized production bundle
- Committed: No (in .gitignore)
- Contents: Vite generates minified JS, CSS, and asset hash files

**supabase/functions/:**
- Purpose: Serverless backend endpoints (Supabase Edge Functions)
- Generated: Manual (created by developers)
- Committed: Yes (in git)
- Notable: `claude-proxy/` function handles secure Claude API integration

**android/:**
- Purpose: Native Android wrapper for mobile app
- Generated: `npx cap sync` syncs web files, `npx cap build` compiles APK
- Committed: Yes (gradle config, source code)
- Build output: `.apk` files (in .gitignore)

**.planning/codebase/:**
- Purpose: GSD (Get Shit Done) generated analysis documents
- Generated: By automated CI/CD or `/gsd-map-codebase` command
- Committed: Yes (markdown files for reference)
- Content: ARCHITECTURE.md, STRUCTURE.md, CONVENTIONS.md, TESTING.md, CONCERNS.md

## Import Patterns

**React imports:**
```javascript
import { useState, useEffect, useRef, useCallback } from "react";
import { createRoot } from "react-dom/client";
```

**Supabase:**
```javascript
import { createClient } from "@supabase/supabase-js";
```

**Local imports:**
```javascript
import { db } from "./lib/supabase";
import App from './App.jsx';
```

**No bundler path aliases** — imports use relative paths (./lib/supabase, ./App.jsx)
