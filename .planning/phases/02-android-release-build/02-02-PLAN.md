  <read_first>
    - android/app/build/outputs/bundle/release/app-release.aab (the built artifact — confirm it exists before verifying)
    - .planning/phases/02-android-release-build/02-PATTERNS.md (jarsigner verification command and expected output format)
  </read_first>
  <files>None modified — verification only</files>
  <action>
    Run the jarsigner verification command (per D-05):

    ```bash
    jarsigner -verify -verbose -certs android/app/build/outputs/bundle/release/app-release.aab
    ```

    **What to confirm in the output:**
    1. The output contains the text `jar verified.` — this means the AAB is properly signed
    2. The certificate DN (Distinguished Name) in the output should be recognizable as the one generated for this project (the alias `aifluent` itself does not appear verbatim in jarsigner output, but the cert's subject/issuer DN will match what was entered during `keytool -genkey`)
    3. `WARNING` lines about "This jar contains entries whose certificate chain is not validated" are NORMAL for a self-signed release keystore — these are NOT failures. Do not treat them as errors.

    **If verification fails** (output says `jar is unsigned` or contains `UNSIGNED`):
    - Check that `android/keystore.properties` exists and has correct values
    - Check that `android/ai-fluent-release.keystore` exists at the path referenced in keystore.properties
    - Re-run `./gradlew bundleRelease` from the `android/` directory

    After verification, report the file size of the AAB for reference:
    ```bash
    wc -c < android/app/build/outputs/bundle/release/app-release.aab
    ```
  </action>
